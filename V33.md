## Architecture and matched recipe

All configurations use exactly `train_multi.py`'s 168-input preprocessing, train/holdout split, statistics sample, shuffled sequence batches, mask cache, loss, optimizer, schedule, evaluation and budget. One shared batch stream feeds all three models. Each model is reseeded independently by the existing trainer; the projection also has a forked CPU initialization RNG, seed 33,000,000 + model init seed. B and C start with identical projections. Adding B/C leaves A unchanged (checked against the original trainer).

| Configuration | GRU input | Parameters |
|---|---|---:|
| A: `gru` | Original 168 inputs | 213,762 |
| B: `v33proj` | z = tanh(Linear(168,32)) | 166,946 |
| C: `v33context` | concat(z, z−a8, z−a64, z−a512), 128 dimensions | 203,810 |

Every model has a 2-layer, hidden-128 GRU with no dropout, followed by Linear(128,2). A uses the original model class without modification. Averages are inclusive: a_h[t] = d_h a_h[t−1] + (1−d_h) z[t], d_h = 2^(−1/h), half-lives 8,64,512 rows. All scales initialize **exactly** to the first projected row, making first-row deviations zero. C state is `(GRU hidden [2,B,128], averages [B,3,32])`. B uses the same state interface, with an unused zero average tensor.

`v33_model.averages` implements a differentiable affine prefix scan in blocks of at most 64 rows. Decay powers have exponents at most 32; there are no inverse powers, long-sequence products, detached features or precomputed learned features. State passes between scan blocks with its graph intact. The unchanged trainer carries state between 1,000-row chunks and detaches both tensors after each optimizer update. It resets state only for a new batch of independent sequences. All warm-up rows update projection, averages and GRU; only the loss excludes steps below 99.

Full recipe: data/init seed 0, train holdout 300, valid 1,873, n-stats 64, batch 16, chunk 1,000, 5 epochs = 64,500 updates/model, AdamW lr 0.001, wd 0.05, cosine decay, gradient norm clip 1.0. Row weight is `(abs(clip(y)) + .05) * (.5 + .5 * min(p/mean_p,20))`; predictions and targets clipped to [-2,2] in the existing weighted MSE. No changes to the mask probability cache or mean-p calculation.

## Correctness evidence

Machine-readable results: `v33_results/correctness.json`, `gpu.json`, `onnx.json`.

- Future-input perturbations: exactly zero change to earlier outputs for A/B/C.
- Whole 211-row evaluation vs chunk lengths 1,17,64,100: maximum absolute errors A 1.49e−7, B 5.22e−8, C 8.94e−8. This includes single-row streaming and scan-block boundaries.
- Reset reproducibility: exact. Processing 99 warm-up rows, then continuing: error at most 4.85e−8. All-scale first-row initialization is exact.
- Every half-life propagates finite gradients to earlier projected rows across scan blocks, matching its analytical derivative within 1e−7. A loss depending **only** on averages reaches projection weights (gradient norm 33.22), excluding the direct z-to-GRU path as an explanation. Explicit detachment removes graph history from both carried states.
- 20,000-row EMA stress check: finite throughout; maximum error against a serial float64 recurrence 9.61e−6. Separate 1,000-row serial float32 comparison max 1.24e−5.
- Ten synthetic GPU updates: original `train_v2m.GRUModel` and A have bitwise-equal losses and final weights.
- Four real-cache updates, batch 2, same seed, mask weighting, stats from two sequences, valid subset 1 and holdout 300: A's weights, stats, valid, valid-all and holdout results exactly equal the unchanged `train_v2m.py` trainer. B/C also complete training/evaluation/checkpoint saving. Tiny smoke scores are not evidence of predictive quality.
- The actual `train_v33.py` entry point is smoke-tested separately; checkpoint loading works through `v33_model.register().load_model(path)`.

## Original prepared command (superseded by V33_RUN_20261109.md)

Run only when the shared machine is free, following the team's one-training-job rule. The output directory must not exist; the entry point refuses to reuse it. `noclobber` also protects the nohup log. The 2.5 GiB allocation cap is set by the v33 entry point. No external messages are sent by these scripts.

```bash
cd /home/jovyan/work/varanasi-lob-ml
nvidia-smi
ps -ww -eo pid,args | rg 'train_.*py'
set -o noclobber
CUDA_VISIBLE_DEVICES=0 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
nohup /home/jovyan/work/venv/bin/python train_v33.py \
  --output-dir "$PWD/checkpoints/v33_full_20261108" \
  --models 'v33a_control:0:gru::0,v33b_projection:0:v33proj::0,v33c_context:0:v33context::0' \
  --data-seed 0 --run v33_full_20261108 \
  --hidden 128 --epochs 5 --batch 16 --chunk 1000 \
  --lr 0.001 --wd 0.05 --alpha 0.5 \
  --n-val 1873 --n-holdout 300 --n-stats 64 --eval-every 12800 \
  --mask-p /home/jovyan/work/cache/train_maskp.npy \
  > v33_full_20261108.nohup.out 2>&1 &
```

New checkpoints and all per-model/combined logs go inside that fresh output directory, under the repository's ignored `checkpoints/` tree. Legacy export/load tools require registering v33 classes first; they do not independently support the new architectures. Do not pass unrelated experimental options such as auxiliary/classification heads or dropout to the v33 configs.
